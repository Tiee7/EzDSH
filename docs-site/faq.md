# 常见问题

## 基础概念

### 我必须配置 API key 才能使用吗？

要真正使用 AI 功能，需要配置至少一个模型供应商的 API key。没有 API key 时应用可以正常打开，但无法调用模型，界面会提示你先配置供应商。

API key 是调用模型服务（例如 DeepSeek）的凭证。首次使用的大致流程是：

1. 打开 EzDSH，进入 Harness 工作界面；
2. 在界面提示下选择模型供应商；
3. 填入该供应商的 API key；
4. 开始第一个会话。

### API key 是什么？我在哪里可以获得？

API key 是向模型服务商申请到的私密凭证字符串，相当于「调用模型的钥匙」。服务商会根据 key 识别你的账号并按使用量计费。

获取方式：到对应服务商的开发者平台注册并创建一个 API key。例如：

- **DeepSeek**：在 [platform.deepseek.com](https://platform.deepseek.com) 注册并创建 API key；
- 其他供应商：到各自官网的开发者平台创建。

EzDSH 不限定供应商，支持 DeepSeek、OpenAI、Anthropic、Google Gemini、Moonshot/Kimi、Kimi Code、MiniMax、Z.AI/GLM、Mistral、OpenRouter、Groq、Together AI、火山引擎等。你申请的 key 只会用于你选择的这家供应商。

### EzDSH 是什么？我能用它做什么？

EzDSH 是 DeepSeek Harness 的桌面客户端。它把 DeepSeek Harness（一个本地 AI 工作台）封装成开箱即用的桌面应用：安装后直接打开，自动在你自己的电脑上启动 AI 运行时并加载工作界面，不需要安装 Node.js，也不需要操作命令行。

你可以用它和 AI 对话，也可以让 AI 帮你处理任务，比如写代码、执行命令、分析文件等。DeepSeek Harness 负责 AI 的能力，EzDSH 负责给你一个稳定、好用的桌面入口。

### EzDSH 和 DeepSeek 网页 / App 有什么区别？

- **DeepSeek 网页 / App** 是云端服务：你的对话数据保存在云端，只能使用 DeepSeek 自己的模型。
- **EzDSH** 是本机桌面应用：AI 运行时在你自己的电脑上运行，会话与数据保存在本地，并且不限于 DeepSeek——你可以配置多个模型供应商并在它们之间切换。

简单说：网页/App 是把数据交给云端；EzDSH 是把 AI 装进你的电脑，数据由你自己掌控。

## 第一次使用

### 打开后看到一个网页界面，我该做什么？

你看到的界面是 DeepSeek Harness 的 Web UI（工作空间）。如果还没有配置供应商，界面会提示你配置；跟着提示选择模型供应商、填入 API key，然后新建一个会话开始提问即可。

不需要手动保存——你的会话会自动保留在本地，关闭应用再打开后依然在。

### 怎么选模型供应商、怎么填写 API key？

在 Harness 工作界面的配置里选择供应商（例如 DeepSeek、OpenAI、Kimi 等），把你在对应平台申请的 API key 粘贴到输入框，保存即可。配置完成后就可以在该供应商下使用模型。

当前版本由 DeepSeek Harness 的 Web UI 负责供应商配置，EzDSH 会直接使用这套配置启动运行时。

### 关掉软件后，我的对话数据会丢吗？

不会。EzDSH 是本地优先的应用，你的会话、配置、Profile、Plugin 和日志都保存在你电脑的本地目录里。关闭应用只是停止运行时进程，数据不会被删除，下次打开会自动恢复。

## 安全 / 隐私

### 我的 API key 会被上传或泄露吗？

不会。API key 只保存在你本机的凭据文件里，且使用受限权限写入。它不会进入浏览器的本地存储，不会写入普通日志，也不会发送到任何云端后台，只用于和你选择的模型服务商通信。

### 我的对话数据存哪里？会同步到云端吗？

存在你本机。会话和项目数据保存在应用的本地数据目录，不依赖任何云端后台，也不会同步到云端。应用升级不会删除这些数据。

### 为什么这个软件只在本机运行？

这是「本地优先」的设计目标。DeepSeek Harness 的 AI 运行时和你的数据都运行、保存在你自己电脑上，运行时只监听本机地址 `127.0.0.1`，外部网络无法直接访问。这样你的模型调用、API key 和项目数据都由你自己掌控。

## 故障排查

### 打开后白屏 / 一直转圈怎么办？

白屏或一直转圈通常是本地 AI 运行时还没有就绪。可以这样处理：

1. 等待几秒，让它完成启动检查；
2. 关闭应用后重新打开；
3. 查看运行日志，确认启动卡在哪个环节；
4. 确认没有其他程序占用端口。

如果持续失败，请查看日志并反馈。

### 提示启动失败 / 健康检查失败怎么办？

应用启动 DeepSeek Harness 运行时后，会在约 30 秒内做健康检查，失败时提示原因。常见原因和处理：

- **端口被占用**：应用会自动检测并重试，多次重试仍失败时，关闭冲突程序后重启应用；
- **启动超时**：关闭占用资源的大型程序后重试，或重启电脑后再试；
- **数据目录权限异常**：确认当前用户对应用数据目录有读写权限。

如果仍然失败，打开日志查看具体报错，并连同日志一起反馈。

### 去哪里查看日志和报错信息？

打开应用设置里的「运行日志」按钮（设置 → 运行时 → 打开日志），会用系统默认程序打开日志文件。

也可以手动找到日志文件：

- **macOS**：`~/Library/Application Support/EzDSH/logs/harness.log`
- **Windows**：`%APPDATA%\EzDSH\logs\harness.log`

反馈问题时带上日志内容会更有帮助。

## 更新 / 卸载

### 怎么更新？更新会丢我的数据吗？

EzDSH 会自动检查更新，发现新版本时提示你，确认后应用内更新。

更新只替换客户端和 AI 运行时，**不会删除**你的配置、会话、Profile、Plugin、日志和本地工作数据，更新后无需重新配置。

### 想卸载怎么卸载？数据会保留吗？

卸载方式：

- **macOS**：把 EzDSH 从「应用程序」移到废纸篓；
- **Windows**：在系统「设置 → 应用」中卸载，或运行安装程序选择卸载。

卸载会删除程序本身，但本机的数据目录（配置、会话、日志等）默认保留；如果需要彻底清除，可以手动删除数据目录。
