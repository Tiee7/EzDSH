# 插件变更等待正常模式验证

2026-09-14，基线 `a5f6c2a`。

## 问题与原因

当上一项 DSH 插件安装、更新、启用、停用或卸载尚未在正常模式启动成功时，Main 会阻止修改另一个插件。安全模式和隔离模式不加载正常 profile 中的第三方插件，因此在这些模式重启只能证明受限环境可用，不能证明刚才的插件变更安全。

此前这道门禁在商店里被通用安装诊断归为未知问题，用户会直接看到 `Restart Runtime before changing another DSH plugin` 或更长的内部英文说明。第二次操作的失败状态还会覆盖上一项操作的重启提示，导致用户知道需要启动，却缺少同页入口。

## 用户流程

商店现在把旧短句和当前完整错误识别为“上一项插件变更尚未验证”。中英文界面先显示：

- 暂不能修改其他插件；
- 请正常启动并确认上一项插件变更；
- 安全模式或隔离模式重启不会完成插件验证。

原始英文保留在折叠的技术细节中。错误下方继续显示现有模式操作：在安全或隔离模式中可选择“正常启动并应用插件变更”，也可选择“继续当前模式”。正常启动成功前仍阻止下一项插件修改；本批没有削弱恢复事务或自动认定插件健康。

安装、更新、启用、停用和卸载共用的普通错误卡片标题为“插件操作失败”，日志路径也统一标为“详细操作日志”，避免卸载等失败被误写成安装问题。等待正常模式验证仍使用上面的专用标题。

无法确认 Runtime 兼容性时，界面不再建议用安全模式验证。提示会明确要求安装后正常启动 Runtime；若启动失败，再到恢复页处理该插件。该提示同时使用当前界面的中英文语言。

目录已明确判定版本不兼容时，界面会显示当前 Runtime 版本，并引导用户更新 Runtime 或选择兼容的插件版本。安全模式不能解决版本范围不匹配；精确的上游英文版本要求保留在折叠的技术细节中，不再重复显示通用失败卡片。

“管理已安装”页面与商店详情页共用同一失败提示。删除、更新或启停插件遇到等待验证等结构化错误时，会直接显示本地化原因、处理步骤和折叠的技术细节，不再只显示原始英文消息。
