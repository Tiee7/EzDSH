# 恢复页重试保留模式，日志失败保持可见

2026-09-13，基线 `3b50eec`。

## 用户行为

恢复页的普通重试改为“按当前模式重新启动”。在安全模式或隔离模式中重试时，继续使用原有模式、profile 和数据目录，不隐式执行退出模式、忘记安全模式选择或清理隔离目录。需要恢复扩展时，仍使用明确的“恢复扩展功能并正常启动”或“退出隔离模式并正常启动”。隔离目录仍是临时目录，明确退出后的清理行为保持不变。

重试返回失败、停止或缺少界面地址时，显示错误并允许再次尝试；只有返回 ready 且提供地址，才把结果交给 App。重复点击只发起一次重试；工作区切换事件同步使旧面板回调失效，即使 React 尚未完成面板重建，旧重试的返回结果也不能覆盖新工作区的界面状态。普通卸载仍由面板自己的失效标记保护。

启动失败提示中的“打开日志”即使在技术详情折叠时也可使用。打开失败后，错误始终显示在操作区下方；展开详情不重复显示。再次尝试时清除旧错误并显示忙碌状态。

## 已确认原因与实现

原 RecoveryPanel 普通重试按钮调用 `recovery.exitSafeMode()`。Main 的对应接口停止 Runtime、禁用安全和隔离模式，再显式启动正常模式；隔离控制器的禁用操作会清理临时目录。因此原按钮的“重启”文案没有表达实际模式与数据影响。

普通重试现在调用现有 `runtime.restart()`。RuntimeManager 的无参 restart 保留当前启动上下文；首次模式选择读取失败时，再次启动仍会重新读取选择。本批不改 Main 的模式切换或启动逻辑。

App 继续保留正常模式的恢复门禁：即使 Runtime 已 ready，仍需 Main 成功处理待确认事务并发布非 recovery-required 状态后，才离开恢复页。Renderer 不主动清除插件事务，也不把安全模式启动成功当作正常插件已恢复。

日志失败提示原来位于 `expanded` 条件中；现在仅把现有 alert 移到条件外，不读取额外日志、不上传诊断信息。

## 验证边界

测试先复现普通重试调用退出接口和折叠状态缺少错误提示，再验证修复。真实 React App/RecoveryPanel 使用模拟原生接口；RuntimeManager 和模式控制器使用临时目录、模拟进程与健康检查。隔离目录中的测试工作文件在普通重启后保持原内容，明确禁用隔离模式后才被清理。

工作区切换保护针对当前 Renderer 的旧重试回调，不取消已发送到 Main 的请求，也不是所有模式操作的跨工作区调度机制。ready 仍沿用现有 Runtime 健康判断；完整业务健康、完整服务重建与跨平台发行包验证不在本批范围。
