# 插件启用与历史备份恢复故障

2026-09-14，实际开发版 EzDSH 1.8.1557 / Runtime 0.1.6-alpha.1。

## 已验证原因

- `dsh-skill-hub@1.1.0` 只声明 `dsh.client`，实际 profile patch 已有直接插件行。原启用方法却把每个依赖都加入 `dsh.profile.bundles`，正常启动因 `declares no dsh.bundle` 退出。DSH CLI 自身只把声明 `dsh.bundle.patch` 的包加入此列表。
- 启用操作成功写入 profile 后，启动前兼容检查仍可能再次停用插件；原流程把正常启动成功当成启用成功，没有在重启前向用户说明已知的不兼容原因。
- `dsh-codex-connect` 要求的 `dsh-client-ui-primitives` 无法从 CLI 的 Node 依赖路径解析，但当前 Web frontend 的实际入口把它注册在浏览器静态模块表中。原检查把“Node 无法解析”误当成“Runtime 不提供”，因此重复停用本可启用的插件。
- 指定 `pre-plugin-change` 备份的 SHA-256 正确。阻断来自旧安装目录的共享依赖链接、已卸载包残留的 `.bin` 入口，以及原本存在的外部技能链接，不是归档损坏。

## 修复行为

启用前读取实际包元数据和 profile patch。bundle 插件按 bundle 层启用；直接插件仅更新已有 patch 行。缺少元数据、缺少激活入口或已知不兼容时，在停止 Runtime、创建恢复事务和修改配置前返回可见失败。停用不执行启用预检。

正常启动前移除旧启用逻辑误写的非 bundle 层，保留直接插件配置和安装文件。兼容检查覆盖有效 bundle 与启用中的直接 patch 插件，并尊重缺失的 optional peer。

对 Node 无法解析的已知浏览器平台依赖，只检查当前 CLI 选中的 Web frontend 元数据、`dist/index.html` 实际引用的包内入口和 boot 的静态模块注册表。源码目录中仅存在同名包不足以通过检查。DSH 官方工作区约束要求整个 DSH 包族采用同一发布版本，因此同时满足同版本依赖声明和实际 seed 注册时，使用该 frontend 版本检查插件的 peer 范围；未知构建形式仍不能判为兼容。

桌面恢复与独立 `rescue.mjs` 使用相同边界：

- 仅在 staging 中清除受管共享依赖目录下可识别的旧安装链接，交给当前 Runtime 重建；跨开发版/安装版只识别具有 EzDSH 元数据和主入口的 `Resources/app`。
- `.bin` 仅处理相对路径指向已完全不存在包的孤儿入口。目标包存在但可执行文件丢失、越界或未知链接仍拒绝恢复。
- 外部技能链接仅在当前 live 环境同位置已有链接，且原始目标和 realpath 都完全相同时保留。归档不能新增外部位置或改变已有目标；新机器没有该基线时仍拒绝。
- 不修改源归档、用户插件文件或凭据；恢复继续执行原有校验和、staging 和恢复前快照流程。

## 实际验证

对用户指定备份的临时副本，分别执行桌面 `restore(name, false)` 与独立脚本完整恢复。使用真实恢复配置，只复制原本存在的技能链接作为 live 基线，没有复制凭据保险库。

两入口均成功；每份恢复的 1,089 个普通文件逐字节 SHA 匹配，包含 178 个第三方插件文件。495 个保留的符号链接全部有效；原归档与两份副本的校验和均未改变。AppleDouble 元数据单独统计。缺失本机凭据保险库时正确报告凭据需重新输入。

真实 skill-hub 配置副本在修复前以相同错误退出 1，修复后 `--dump-config` 退出 0，仍包含 skill-hub 的直接插件行。完整恢复副本也成功生成 Runtime 配置。当前 live profile 修复前另存了 package.json 与 patch 副本，只移除错误 bundle 层后，实际应用正常启动并显示 Runtime 工作区。

实际 Skill Hub 设置页已渲染，并显示 8 个 Agent、134 个已发现技能。实际 Codex Connect 安装包的启用预检也已通过当前 Runtime 的浏览器模块版本证据。

这些验证证明备份可恢复、配置可组装和正常启动已恢复；不代表所有第三方插件的业务功能或模型请求都已验证。原有 `dry-run` 仍只检查归档列表与校验和，完整链接检查发生在实际恢复的 staging 阶段。

最终回归为 32 个文件、431 项测试通过；Main 和 Renderer 类型检查、构建、独立恢复脚本语法检查及差异空白检查通过。构建保留既有 workflow-run-store 静态/动态混合导入提示。
