# 启动失败页复用还原与启动重试流程

2026-09-13，基线 `571e8a2`。本批将启动失败页的“恢复此故障关联的备份”和“恢复指定备份”接入设置页已采用的恢复流程。

## 用户流程

历史备份继续按时间倒序列出，保留单选。选择后点击“查看还原详情”，应用先预览，再在唯一的确认框中说明具体备份日期、会替换的数据、缺失凭据类别、执行前备份和应用版本不会回退。取消确认时不还原、不重启，列表和原选择保留。

故障关联备份必须通过完整名称找到同一份备份后才进入预览和确认。关联备份已不可用时，提示重新选择，不自动改用最近一份或其他备份。

确认后自动还原并尝试启动。只有 Runtime ready 才显示启动成功；数据已还原但启动失败时保留“重试启动”，重试不再次还原数据。启动期间页面卸载、重新挂载不丢失结果。其他恢复动作进行中时，共享重试按钮也会禁用，避免两条操作争用。

## 实现边界

- `useRecoveryRestore.restore` 同时接受已选备份对象与完整备份名称。名称查询也纳入同步 busy 和 generation 保护；工作区切换后的迟到列表或预览不能发起新工作区的还原。
- 返回值只表示本次数据是否已还原且操作仍有效。启动失败也返回已还原，选择器可以关闭并交给启动重试；取消或失效不关闭原选择器。
- App 持有还原状态，RecoveryPanel 渲染该状态和合并忙碌状态后的操作入口。工作区开始切换时同时重建 RecoveryPanel，清空历史列表和选择；旧实例的迟到列表结果不会成为新工作区的选择。
- 插件事务回滚仍是独立动作，本批没有将其混入“恢复某份备份”，也没有改变其授权范围或自动执行策略。
- 本批不提供窗口重载或应用退出后的持久化续接，不取消已发到 Main 的还原操作，也不证明全部外部服务或业务能力已经恢复。预检、归档字节变化、完整服务重建的限制继续见 [恢复预检记录](recovery-preflight.md)。

## 验证

验证使用模拟原生接口和真实 React App/RecoveryPanel，不执行真实用户备份还原或启动用户 Runtime。新增反例覆盖确认取消、关联备份丢失、页面卸载、只重试启动、历史列表加载期间禁用启动重试，以及工作区切换后的迟到列表和还原结果。

- 21 个定向测试文件、237/237 通过，涵盖恢复归档、独立救援、预检协调、模式资源、Runtime 生命周期与 Renderer 交互。
- 新增真实 App/RecoveryPanel 集成测试 9/9；独立审查重跑 6 个 Renderer 文件、74/74 通过，未发现本批新增的 P1/P2 问题。
- Main、Renderer 类型检查与构建通过；构建保留既有 workflow-run-store 动态/静态混合导入提示。
- 本地浏览器使用真实 RecoveryPanel、模拟原生接口，确认备份倒序、未选择时禁用查看、选择后可查看，以及唯一确认框中的备份日期、替换范围和缺失凭据类别。浏览器工具处理原生确认框时阻塞，取消后保留选择和只重试启动由自动化测试验证，本批不宣称完成浏览器全流程或发行包验收。
