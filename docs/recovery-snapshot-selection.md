# 最近备份选择与独立救援的一致性

2026-09-13，基线 `68145bf`。本批继续落实环境恢复规划，修正有备份却不能使用默认恢复入口的问题。

## 用户得到的改进

- 应用内恢复与独立救援的 `latest` 都选择现有备份列表中创建时间最新、且不是 `pre-restore` 的一份。多份备份不再被误认为选择不明确；独立救援省略名称时沿用这个默认行为。
- 插件变更前生成的 `pre-plugin-change` 备份也可在独立救援中查看、校验和恢复。应用无法启动时，不会仅因备份类型漏识别而找不到这份备份。
- 普通名称前缀匹配多份时仍要求明确选择。选中的归档摘要不匹配时报告错误，不自动改用更旧的数据。
- Main 的单次 `RecoveryManager.restore` 调用使用已选定的同一份 manifest 进行摘要校验和后续还原判断，避免校验第二次读取的元数据，却按第一次读取的元数据执行。

没有新增自动还原动作。独立救援 CLI 的 restore 仍默认只预览，只有显式 `--yes` 才替换数据；救援网页仍要求 `POST apply=1`，应用现有确认流程保持不变。共享选择器也服务于删除和备注修改：明确传入 `latest` 现在能在多份备份中选中最近一份，而 UI 仍使用完整备份名称。额外验证了待完成更新或插件变更所需的备份即使通过 `latest` 指定，也不会被删除；无待恢复事务时，显式删除只影响选中的一份。

## 证据与验证

新增测试使用临时目录、实际 tar 归档和实际独立救援子进程，不读取或还原真实用户备份。

- Manager 新增 12 项回归：多份备份的校验/预览/真实还原、跳过安全副本、更新和插件变更备份、无候选、普通前缀歧义、损坏摘要不回退，以及明确删除的范围和待恢复事务的删除保护。
- 同一 manifest 的两项反例通过可控文件变化复现：第一次选中错误摘要后，磁盘上的 manifest 被更换为正确摘要。旧实现预览和真实还原都错误地通过；新实现按首次选定的摘要拒绝，当前设置、凭据和备份前状态不变。
- 独立救援新增 7 项回归：默认/显式 latest、插件备份列表/校验/预览/实际还原、保留原数据目录、无候选、空名称、前缀歧义、选中归档损坏。真实还原仅操作测试临时目录。

8 个定向测试文件、88/88 通过；Main 和 Renderer 类型检查、构建、独立救援脚本语法检查、diff 检查均通过。构建仍提示既有 `workflow-run-store` 动态/静态混合导入，不影响本批构建结果。

## 明确保留的边界

- “最近”限于现有列表能识别并解析 manifest 的备份。列表仍忽略不完整或无法解析 manifest 的项；本批不改变时间排序和格式校验策略，也不宣称任何形式的损坏都不会导致较旧项成为候选。
- 同一 manifest 不代表归档字节已锁定。摘要校验之后归档仍可能被其他进程改写；完整预解压、不可变输入和磁盘写入验证仍需后续处理。确认预览与实际还原也是独立调用，仍保留实际执行时重新校验。
- 已复制到用户备份目录的旧救援脚本不会凭这次源码提交自动更新；应用执行现有初始化或生成备份流程时才会复制新版。未修改真实用户目录，未发布安装包。
- 本批不完成全部服务实例重建、业务能力就绪验证、恢复中断续接或跨平台发行验收。整体计划见 [环境恢复设计](environment-recovery-design.md)，上一批执行记录见 [恢复预检与启动重试](recovery-preflight.md)。
